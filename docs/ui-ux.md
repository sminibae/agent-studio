# UI / UX

이 문서는 제품 UI의 성격과 설계 원칙을 정의한다. 이 제품은 일반적인 SaaS 대시보드가 아니라 데이터를 자세히 살펴보는 개발자 도구다.

카드 그리드, 넓은 여백, 큰 숫자 타일, 파스텔 차트를 관습적으로 배치하지 않는다. 화면은 시각적인 인상보다 데이터를 정확하고 빠르게 읽는 데 초점을 맞춘다.

UI를 구현하기 전에 이 문서를 읽는다. 여기에서 정한 규칙을 따르지 않을 때는 변경 이유를 기록한다.

---

## 성격

| 축 | 이 제품 | 아닌 것 |
| --- | --- | --- |
| 성격 | 개발자 도구 | 경영 대시보드 |
| 정보 밀도 | 높다 | 여백 중심 |
| 기본 표현 | 테이블 | 카드 |
| 상세 보기 | 분할 화면 | 모달 |
| 원본 데이터 | 항상 접근 가능 | 요약만 제공 |
| 텍스트 | 축약하지 않음 | 말줄임 위주 |

비교 대상으로 삼을 만한 도구는 로그 뷰어, 프로파일러, APM 트레이스 화면, DB 클라이언트다. 마케팅 대시보드가 아니다.

---

## 규칙

### 레이아웃

- **모든 섹션을 Card로 감싸지 않는다.** Card는 다른 내용과 구분되는 경계가 필요한 블록에만 사용한다. 테이블은 Card 안에 넣지 않는다.
- **비교 가능한 구조화된 데이터는 테이블로 표현한다.** Run 목록, Case Run 목록, Setup 비교, 지표 비교는 전부 테이블이다.
- **목록과 상세 정보를 함께 보는 디버깅 화면은 분할 화면으로 만든다.** 왼쪽에는 목록을, 오른쪽에는 상세 정보를 표시한다. 목록에서 항목을 선택하면 오른쪽 영역만 갱신한다.
- **상세 정보를 모달에 넣지 않는다.** 모달은 기존 화면을 가려 정보를 나란히 비교하기 어렵게 한다. 삭제 확인처럼 짧은 결정에만 사용한다.
- 화면 너비를 제한하지 않는다. 테이블과 Trace는 넓은 화면을 충분히 활용한다.
- 세로 스크롤은 허용한다. 정보를 숨겨 스크롤을 줄이지 않는다.

### 테이블

- 기본 정렬은 사용자가 가장 먼저 찾는 것을 위로 올린다. Case 목록의 기본 정렬은 점수 오름차순이다. 잘 푼 Case가 아니라 못 푼 Case를 먼저 본다.
- 숫자 열은 우측 정렬하고 자릿수를 맞춘다.
- 상태는 색 하나에만 의존하지 않는다. 색과 텍스트를 함께 쓴다.
- 행 높이를 키우지 않는다. 한 화면에 더 많은 행이 보이는 편이 낫다.
- 열이 많으면 숨기지 않고 가로 스크롤을 제공한다. 다만 이름이나 Case처럼 대상을 식별하는 열은 고정한다.

### 텍스트와 코드

- **프롬프트, JSON, 도구 인자, 도구 결과, 모델 출력에는 고정폭 글꼴을 사용한다.**
- 긴 텍스트는 접어 두되 항상 펼칠 수 있게 한다. 펼친 상태를 기억한다.
- JSON은 구문 강조와 접기를 지원한다. 원본 문자열 복사 기능을 함께 제공한다.
- 텍스트를 말줄임으로 잘라 놓고 전체를 볼 방법을 주지 않는 화면을 만들지 않는다.

### 식별자

- **이름과 버전을 우선 표시하고 UUID는 보조로 표시한다.** `checkout-agent-prompt v7`이 먼저고 UUID는 회색 작은 글씨다.
- UUID는 클릭 한 번으로 복사할 수 있게 한다.
- Setup은 생성 후 변경할 수 없으며 같은 이름을 사용할 수 있으므로, 이름과 생성 시각을 함께 표시한다.

### 상태와 실패

- 실패를 숨기지 않는다. `partially_failed 17/20`처럼 Run 상태 옆에 성공 및 실패 개수를 항상 함께 표시한다.
- 데이터가 없을 때는 빈 화면만 표시하지 않고 다음에 할 수 있는 작업을 한 문장으로 안내한다.
- 로딩 중에는 레이아웃이 흔들리지 않게 한다. 테이블은 스켈레톤 행을 쓴다.
- 오류 메시지에는 원본 오류를 포함한다. "문제가 발생했습니다"와 같은 일반적인 문구만 표시하지 않는다.

### 숫자

- `Pass Rate 65% (13/20)`처럼 지표 옆에 분모를 함께 표시한다.
- 반복이 1인 Scope에서 분산 지표 자리에 0을 표시하지 않는다. "반복 없음"으로 표시한다.
- 차이값은 부호와 함께 보여준다. `+0.12`, `−3`.
- 소수점 자릿수를 화면 전체에서 통일한다. 점수는 소수점 2자리, 비율은 정수 퍼센트 + 괄호 안 분수.

### 컴포넌트

- shadcn/ui를 우선 사용한다. 새 컴포넌트를 만들기 전에 기존 것으로 되는지 확인한다.
- 아이콘만으로 동작을 표현하지 않고 텍스트 레이블을 함께 표시한다.
- 애니메이션은 상태 변화를 알리는 용도로만 쓴다. 장식용 전환을 넣지 않는다.
- 차트는 비교 관계를 이해하는 데 필요한 경우에만 사용한다. 테이블만으로 충분히 전달할 수 있는 정보는 차트로 바꾸지 않는다.

## 내비게이션

```
상단 탭        Setups | Experiments | Analytics
좌측 탭        각 영역의 하위 섹션
본문           목록 또는 분할 화면
```

- 상단 탭과 왼쪽 탭은 항상 표시한다.
- **Analytics에서는 선택한 Scope를 상단에 고정한다.** 탭을 이동해도 Scope를 계속 표시하여 현재 데이터의 범위를 확인할 수 있게 한다.
- 깊이 들어간 화면에서 빠져나올 경로를 항상 제공한다. Trace에서 Run으로, Run에서 Experiment로.
- 상태를 URL에 담는다. 선택한 Run, 선택한 Case Run, 펼친 탭이 URL에 있어야 링크를 공유할 수 있다.

Setup을 변경할 수 없다는 사실을 화면 상단에 명시하고, 수정 버튼 대신 복제 버튼을 제공한다.

왼쪽에는 가로로 긴 박스 형태의 Case Run 목록을 표시하고, 오른쪽에는 선택한 Trace를 표시한다. 오른쪽 영역은 이벤트 시퀀스와 선택한 이벤트의 상세 정보로 다시 나뉜다.

이벤트 상세에 표시할 것: Input, Output, Latency, Token, Model, Tool Arguments, Tool Result, Error.

### Analytics

```
┌ Scope:  2 Setups × 20 Cases × 3 Repeats  (N×N×N)             │
│ "평균 성능 + 안정성까지 어느 Setup이 낫나?"      [Change Scope]│
├─────────┬────────────────────────────────────────────────────┤

│ Overview│ checkout-v2  0.81   75%     0.06  —         baseline│
```

Scope는 상단에 고정한다. 사용자가 각 Regression을 바로 확인할 수 있도록 개수와 Case 목록을 함께 표시한다.

## 판단이 필요할 때

새 화면을 설계할 때는 다음 질문을 순서대로 검토한다.

1. 데이터를 서로 비교해야 하는가? 그렇다면 테이블을 사용한다.
2. 상세 정보를 보면서 목록의 맥락을 유지해야 하는가? 그렇다면 분할 화면을 사용한다.
3. 요약 정보에서 원본 데이터로 이동할 수 있는가? 없다면 이동 경로를 추가한다.
4. 화면에 숫자의 분모가 표시되어 있는가? 없다면 분모를 추가한다.
5. Card가 정보의 경계를 나타내는가? 장식에 불과하다면 제거한다.

## 열린 질문

- **다크 모드.** 개발자 도구 성격상 필요할 가능성이 높지만 우선순위는 정해지지 않았다. shadcn 기본 테마를 쓰면 비용은 크지 않다.
- **Trace 이벤트가 수백 개일 때.** 가상 스크롤이 필요한지, 이벤트를 접어서 요약할지 정해지지 않았다.
- **Case × Setup 매트릭스의 규모.** Case가 수백 개가 되면 매트릭스 테이블이 읽히지 않는다. 필터와 정렬로 버틸지, 다른 표현이 필요할지는 실제 규모를 보고 정한다.
- **키보드 내비게이션.** Trace를 위아래로 넘기는 단축키는 디버깅 속도에 직접 영향을 준다. MVP에 넣을지 정해지지 않았다.
