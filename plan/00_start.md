# 구현 시작 계획

## 목적

이 문서는 분야별 구현 계획을 만들기 위한 뼈대다.

- 설계 기준은 [docs/README.md](../docs/README.md)와 [docs/decisions.md](../docs/decisions.md)를 따른다.
- 아래 분야를 필요에 따라 나누거나 합쳐 `plan/NN_something.md`를 작성한다.
- 각 분야의 세부 결정과 구현은 해당 계획에서 진행한다.

## 큰 순서

| 순서 | 분야 | 대략적인 범위 |
| --- | --- | --- |
| 01 | 프로젝트 골격 | 프런트·API·DB 연결, migration, 개발 명령·CI, 인증·owner 경계 |
| 02 | 실행 기술 검증 | SDK 호환성, Python 실행 격리와 제한 검증 |
| 03 | 자산과 Setup | Python 자산 계약, 편집·미리보기, Git 저장·Version 발행, Setup 생성·복제 |
| 04 | 실험 실행 | Experiment·Batch·Run·Case Run, fake Agent, worker, 상태·취소·Trace |
| 05 | 실제 Agent 연결 | OpenAI 모델과 날씨 HTTP 도구, 실제 호출 확인 |
| 06 | 평가 | Rubric·Judge·Scoring, 평가 상태와 결과, 동적 평가 조건 |
| 07 | 분석과 비교 | Scope·지표, Setup 비교, Case에서 Trace까지 탐색 |
| 08 | 배포와 운영 | 로그인 설정, 배포, 장애 복구·백업, 첫 완주 검증 |

각 분야는 필요한 화면·API·저장을 함께 연결한다. 상세 순서와 의존성은 분야별 계획을 작성할 때 조정한다.

## 분야별 계획에 적을 것

- 목표와 이번 범위
- 구현 전에 정할 미결사항
- 작은 구현 단위와 순서
- 완료를 확인할 방법
- 참고할 설계 문서와 선행 작업

## 시작할 때 확인할 것

- 골격에서 런타임·패키지 버전과 실제 개발 명령을 정한다.
- 자산 구현 전에 결과 변수·입력·실행 시점과 고정 관계를 정한다.
- 실행기 구현 전에 SDK와 Python 격리를 검증한다.
- 평가·비교 구현 전에 동적 평가 결과의 비교 조건을 정한다.
- 배포 설정은 배포 전에, 보존·영구 삭제 정책은 실사용 데이터 반입 전에 정한다.

## 첫 완성본 기준

Setup 구성 → 실험 실행 → 평가 → 비교 → Trace 확인을 화면에서 완주한다.
세부 인수 기준과 검증 방식은 [docs/engineering.md](../docs/engineering.md)를 따른다.
